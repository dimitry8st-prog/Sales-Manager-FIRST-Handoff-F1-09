КОНТРОЛЬНАЯ ТОЧКА 1 — ПЛАН

Публичный API:
HandoffContextError(ValueError): свойство code;
str(exception) возвращает только код ошибки.
assemble_handoff_context(context: dict) -> dict.

План реализации:
1. Проверить структуру всего входа, точные встроенные типы,
   обязательные поля, отсутствие лишних полей и ограничения.
2. Проверить соответствие locale и language_pack_version
   переданному реестру language_packs.
3. Проверить пять полей области данных каждого сообщения.
4. Проверить дубли ID, sequence и ссылок.
5. Проверить наличие фактов и материалов по ссылкам.
6. Создать независимую копию данных и отсортировать списки.
7. Заменить schema_version на FIRST_HANDOFF_CONTEXT_V1.
8. Рассчитать SHA256 канонического JSON по правилу ТЗ.
9. Добавить handoff_id, content_sha256,
   delivery_status=NOT_DISPATCHED.

Порядок ошибок:
INVALID_CONTEXT
LANGUAGE_SCOPE_MISMATCH
MESSAGE_SCOPE_MISMATCH
DUPLICATE_ID
REFERENCE_NOT_FOUND

План тестов:
Минимальный пример и независимая проверка SHA256.
Русский и английский текст, дополнительный язык,
реестр более 100 языков.
Неверные поля, типы, размеры и управляющие символы.
Несовпадение языка, версии и области данных.
Дубли, отсутствующие ссылки, неверные direction/actor.
Сохранение всей истории при ACTIVE, HANDED_OFF, STOPPED.
Стабильность результата при перестановке списков.
Изменение хеша при изменении body с прежним handoff_id.
Неизменность входа и независимость вложенных объектов.
Приоритет ошибок при нескольких дефектах.
